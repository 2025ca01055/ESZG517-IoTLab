Q1. What transport protocol does MQTT use? What transport protocol does CoAP use? What   is the fundamental difference between the two?
	Answer:
	MQTT uses TCP as its transport protocol, while CoAP uses UDP. TCP provides reliable, ordered delivery of data, whereas UDP is connectionless and has lower overhead but does not guarantee delivery.

Q2. In today's session, MQTT used a publish/subscribe model and CoAP used a request/response model. Explain the difference using the smart home scenario.
	Answer:
	In MQTT, sensors publish data to a broker, and devices that subscribe to a topic automatically receive updates. For example, a temperature sensor publishes readings, and the respected device receives 	them instantly. In CoAP, the respected device sends a request to the smart light and receives a response directly, such as requesting the current light status or changing it.

Q4. In your L3 MQTT publisher, the light relay topic used retain=True. CoAP does not have a retain flag. How does CoAP handle the same problem?
	Answer:
	CoAP stores the current state on the server. When a client wants to know whether the light is ON or OFF, it sends a GET request, and the server returns the current state.

Q5. MQTT uses TLS for security. CoAP uses DTLS. Why can't CoAP use TLS? What is the key difference?
	Answer:
	TLS works with TCP, while CoAP uses UDP. Therefore, CoAP uses DTLS, which provides similar security features but is designed for unreliable UDP communication.

Q6. In a real smart home, where would the CoAP server and client run?
	Answer:
	The CoAP server would run on the smart device, such as an ESP32 controlling a light relay. The CoAP client would run on a mobile app or a home automation controller that sends commands to the smart 	device.

Q7. A student says: "CoAP is always better than MQTT because UDP is faster than TCP." What is wrong with this argument?
	Answer:
	This is incorrect because speed is not the only factor. MQTT is better for applications that require reliable message delivery, such as continuously sending sensor data to the cloud, because TCP 	guarantees that messages arrive correctly.

Q8. In the CoAP server code, render_get returns aiocoap.CONTENT and render_put returns aiocoap.CHANGED. What do these response codes mean? What is the equivalent concept in HTTP?
	Answer:
	aiocoap.CONTENT means the requested data was successfully returned, while aiocoap.CHANGED means the resource was successfully updated. They are similar to HTTP status codes such as 200 OK and 204 No 	Content.

		I.	The MQTT topic name (e.g., smarthome/demo/living_room/relay/light_state), which reveals the device being controlled.

2.	In the TLS demo, the same message was sent but Wireshark showed no readable payload. Explain in one sentence why TLS prevents Wireshark from seeing the message content even though both demos used the same loopback interface.
	Answer:
	TLS encrypts the MQTT data before it is transmitted, so Wireshark can capture the packets but cannot read the message contents without the encryption keys.
